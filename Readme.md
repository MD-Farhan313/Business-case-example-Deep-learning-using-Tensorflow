# Audiobook Customer Repurchase Prediction

An end-to-end TensorFlow classification example that predicts whether an audiobook-app customer will make another purchase. The project prepares a customer-activity dataset, balances its target classes, trains a feed-forward neural network, and evaluates its performance on a held-out test set.

The business use case is to help marketing teams focus retention or advertising spend on customers who are more likely to purchase again. Customer activity from the previous two years is used to predict whether a customer will buy in the following six months.

## Project contents

| File | Purpose |
| --- | --- |
| `Business case Deep Neural network using Tensorflow.ipynb` | The complete workflow: preprocessing, dataset creation, model training, and evaluation. |
| `Audiobooks_data.csv` | Raw, headerless source data with 14,084 customer records. |
| `Audiobooks_data_train.npz` | Preprocessed training split (3,579 samples). |
| `Audiobooks_data_validation.npz` | Preprocessed validation split (447 samples). |
| `Audiobooks_data_test.npz` | Preprocessed test split (448 samples). |

The `.npz` files are generated by the preprocessing section of the notebook and contain `inputs` and `targets` NumPy arrays. They are included so the training section can be run independently after the data-preparation cells have been executed once.

## Data

Each CSV row has 12 values and no header:

1. Customer ID (excluded from modelling)
2. Average purchased-book length (minutes)
3. Total purchased-book length (minutes)
4. Average price paid
5. Total price paid
6. Whether the customer left a review
7. Review score (out of 10)
8. Total minutes listened
9. Completion rate (0–1)
10. Number of support requests
11. Days between the last visit and purchase
12. Target: repurchase indicator (`0` = will not buy again, `1` = will buy again)

The raw data contains 2,237 positive examples and 11,847 negative examples. During preprocessing, the notebook retains all positive examples and removes excess negative examples, yielding a balanced dataset of 4,474 records. It then standardizes the ten input features, shuffles the data, and creates an 80% / 10% / 10% train, validation, and test split.

## Model

The notebook trains a fully connected neural network with:

- 10 input features
- Two hidden `Dense` layers with 50 ReLU units each
- A two-unit softmax output layer
- Adam optimizer and sparse categorical cross-entropy loss
- Batch size of 100 and a maximum of 100 epochs
- Early stopping with a patience of two epochs, monitored on validation loss

The saved notebook output reports a test loss of **0.30** and test accuracy of **86.38%**. Results can differ between runs because the notebook does not set a random seed.

## Getting started

### Prerequisites

- Python 3.10 or another TensorFlow-compatible Python version
- Jupyter Notebook or JupyterLab
- NumPy
- scikit-learn
- TensorFlow 2.x

Install the Python packages in your preferred virtual environment:

```bash
pip install jupyter numpy scikit-learn tensorflow
```

### Run the project

1. Clone or download this repository.
2. Open a terminal in the project directory.
3. Start Jupyter:

   ```bash
   jupyter notebook
   ```

4. Open `Business case Deep Neural network using Tensorflow.ipynb`.
5. Run all cells from top to bottom. The first section regenerates the three `.npz` files; the second section loads them, trains the model, and evaluates it.

Keep the notebook and all dataset files in the same directory, since the file paths are relative.

## Workflow

```text
Audiobooks_data.csv
        |
        v
Remove customer ID → balance classes → standardize features → shuffle data
        |
        v
Train / validation / test .npz files
        |
        v
TensorFlow neural network → validation-based early stopping → test evaluation
```

## Notes for further development

- For a production-quality evaluation, fit the scaler on the training features only, then apply that fitted scaler to validation and test data. The current notebook standardizes before splitting, which lets information from validation and test features influence scaling.
- Consider using a seeded random generator and a stratified split for reproducible, consistently balanced partitions.
- Accuracy alone is not sufficient for a marketing decision. Add a confusion matrix, precision, recall, ROC-AUC, and a threshold/business-value analysis before deployment.
- The current model is not saved after training. Persist the trained model and preprocessing artifacts if predictions need to be served later.
